# 03 — Decisions (only choices a future AI could wrongly undo)
Format: `D<n> · date · decision — why (rejected alternatives)`. Dates for D1–D6 are inferred from project state, not recorded.

- D1 · DuckDB for BOTH analytics and metadata — single-file, zero-ops, fast analytics; column shapes mirror a future Postgres migration (Postgres rejected for now).
- D2 · Auth/RBAC deferred by user — focus on core product; every table already has org/workspace/created_by columns, so no migration needed later.
- D3 · All SQL goes through the sqlglot read-only guard, including AI-generated SQL; `/api/ai/sql` generates but never executes — safety/trust (§19).
- D4 · Explanations, confidence labels and "Why?" attribution are rule-based, not LLM — deterministic, auditable, non-causal wording (§66–67).
- D5 · Gemini free tier is the default AI provider; any provider is configurable in the UI and stored in `ai_providers` — zero-cost onboarding.
- D6 · Python transform layer is sandboxed (AST-validated, whitelisted imports, no builtins; `df` in / `result` out, Polars) — Hex-style SQL+Python without arbitrary code execution.
- D8 · 2026-10-02 · Result cache is invalidated by `engine.writer()` AFTER a write (not by opening a connection) and skips clock/random SQL — invalidating before the write let a racing read cache stale rows.
- D9 · 2026-10-02 · Audit writes are async (single background thread) — each metadata write is ~50 ms (Store opens a connection per call) and must not sit on the query request path.
- D10 · 2026-10-02 · Auto-refresh is opt-in per dataset (never default) — it re-imports from external sources, which is a side effect users must choose.
- D11 · 2026-10-02 · Git repo created for revertability: tag `baseline-before-improvements`, work on branch `improve/autonomous`; data copies in `_backups/` (git-ignored).
- D7 · 2026-10-01 · Memory system = `AI.md` entry + `ai-memory/` folder, tiered and size-budgeted — minimize tokens per fresh chat (research: Cline Memory Bank, AGENTS.md/CLAUDE.md guidance that short, specific context files beat long ones).
- D12 · 2026-10-02 · UI stack = shadcn/ui (Base UI flavour) + ReUI registry on Tailwind v4; Astryx removed — ReUI components are written for Base UI (`render` prop), the Radix flavour does not type-check with them. Theme presets map onto shadcn tokens (`--adm-*` → `--background/--card/--primary…` in index.css); `blue-*` follows the accent.
- D13 · 2026-10-02 · Reusable structure + size budget (user instruction): hooks/, components/common, features/<name>, thin pages; files ≤250 lines (hard 400), enforced by `scripts/check_file_sizes.py`. Reuse before writing; extract on the 2nd copy.
- D14 · 2026-10-02 · UI is ReUI-first (user rule). Only ReUI's own primitives (alert, autocomplete, badge, cascader, code-block, data-grid, date-selector, event-calendar, filters, frame, gantt, icon-stack/tile, kanban, number-field, phone-input, rating, scrollspy, sortable, stepper, timeline, tree) are "ReUI"; the rest of reui.io (1,100+ examples, e.g. `chart-*`) are compositions of shadcn parts. Use the primitive when one exists, else shadcn. The first migration only used ReUI badge; corrected by rebuilding DataGrid on ReUI Data Grid, Select on shadcn Select, shell on shadcn Sidebar.
- D15 · 2026-10-02 · Chart options are data, not code: `features/charts/optionSchema.ts` declares each option once (key, kind, scope by type/family, `when`). The studio panel and the dashboard widget panel are the same `OptionsPanel`. Adding an option = one schema line + one read in a renderer. Legacy option names are normalised in `normalizeOptions`.
- D16 · 2026-10-02 · Ask = conversational analyst over ALL tables (research: semantic-layer grounding, clarifying questions, explainability, follow-up context, follow-up suggestions). The model decides SQL; deterministic code validates, executes, picks the chart (`chart_suggest.py`) and writes a factual fallback summary when the model's prose is unusable (free models echo templates).
- D17 · 2026-10-02 · Linked ("live") datasets: importing a table from a DB source can be schema-only (`mode: link`). A VIEW over the attached remote catalog (`remote_<source id>`) lists the dataset; `services/remote.py` attaches the source on demand when a query mentions it and `rewrite_sql` (sqlglot) points the query at the attached table directly. `datasets.remote_table` marks them. Reason for the rewrite: DuckDB's MySQL scanner raises internal binder errors for aggregates through a view. Rows are never copied; every query is a live remote scan (~4-6 s for 1M rows on TiDB).
- D18 · 2026-10-03 · AI dashboards: the model only proposes widgets as JSON (title/type/SQL); the server validates each SQL (read-only, bind-check + one repair, execution), derives the encoding from the real result (`chart_suggest.encode`) and lays widgets out. Bad widgets are skipped and reported. The parser takes the LAST object holding widgets/ops (reasoning models quote the format first). Edits replace widgets with NEW charts instead of mutating shared ones.
- D19 · 2026-10-03 · API Studio = Hoppscotch-style request workspaces + JSON Editor Online-style JSON lab (research: reui-agnostic, from the sites' feature lists). The browser cannot call arbitrary APIs (CORS), so REST/GraphQL go through `/api/studio/request`; WebSocket connects straight from the browser. Output is always "turn it into data": snapshot dataset or refreshable `rest`/`graphql` source. CodeMirror 6 chosen as the one editor (also the planned SQL editor).
- D20 · 2026-10-03 · Friendly dataset names in SQL: `services/names.py::resolve` (called first in `engine.execute` / `check_sql`) rewrites a dataset's own name (`FROM Chocolate_Sales`) to its physical `ds_*_id` table (sqlglot, 5 s cache; CTE/notebook-step names, ambiguous names and physical names are left alone). The UI shows and inserts friendly names only; `/datasets/columns` is keyed by them. The user does not want `ds_` prefixes or id suffixes visible. Result `sql` echoes the physical table (aliased to the friendly name).
- D21 · 2026-10-03 · Workbench assistant = tool-using agent (Roo Code / Cline style) instead of one-shot SQL chat: plan -> tool call -> observation loop (max 8 steps), every step streamed and shown as a card, Agent mode may add/edit cells (auto-apply or approve per change), Ask mode is read-only. The model only chooses tools; deterministic code validates/executes (all SQL via `validate_readonly`); notebook writes are never done server-side. Old `AiPanel` removed.
- D22 · 2026-10-05 · Query-builder AI = model proposes the builder's own JSON spec, never SQL (research: Metabase/Superset/Hex 'AI assistants' + our D18/D21 patterns). Layers, cheapest first: (1) `qb_rules` answers simple requests and simple edits instantly with no model (exact, auditable; declines unless EVERY part of the sentence is understood), (2) the model for the rest, validated by `clean_spec` -> `compile_spec` -> LIMIT 0 bind check, with up to 2 self-repairs fed the real error, plus `hints` re-applying dropped 'top N'/'by month' and an 'unchanged spec' rejection. Why rules first: the default free reasoning model (OpenRouter nemotron) takes 30-240 s, burns tokens thinking, and silently ignored 'top 5' and a filter. Linked/remote tables: no DISTINCT lookups (a full remote scan ~20 s) and no LOWER() filters (not pushed down; 23 s vs 5 s): typed text values become an IN list of usual spellings instead.
- D23 · 2026-10-07 · Multi-user = one workspace per Supabase user (`ws_<uuid>`), enforced centrally, not per router. `core/tenant.py` holds the workspace in a ContextVar set by the ASYNC `require_user` dependency (a sync one would lose the change in its worker thread). `Store` stamps/filters `workspace_id` on every insert/list/get/update/delete (all tables have the column); `engine` is a router to a per-user DuckDB file (`data/ws/<ws>/analytics.duckdb`, uploads in `uploads/ws/<ws>/`), so a user's SQL cannot even see another user's tables. Auth off = `ws_default` and the legacy files, unchanged. Chosen over Postgres RLS because the data lives in DuckDB; Supabase stays the identity provider. Auth-on hardening (D23b): SQL guard rejects file/network/introspection functions and path-like table names; file/sqlite sources confined to the user's folder; outbound HTTP/DB hosts must be public (redirects re-checked); Python transforms disabled unless ALLOW_USER_PYTHON=true.
